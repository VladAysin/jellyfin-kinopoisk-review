# Проверка на настоящем Jellyfin

Проверено 2026-11-06: опубликованный Kinopoisk Ratings 0.2.0.0,
File Transformation 2.5.2.0 (Release-10.11.5), официальный Docker-образ
`jellyfin/jellyfin:10.11.5`, настоящий Chrome через Playwright.

Образ: `sha256:6d819e9ab067efcf712993b23455cc100ee5585919bb297ea5a109ac00cb626e`.
Сервер слушает только `127.0.0.1:18096`; Kubernetes не используется.

## Подтверждённые результаты версии 0.2.0

- Оба плагина загрузились со статусом Active.
- Сервер добавил загрузчик интерфейса через File Transformation.
- Очередь, состояние подключения и воспроизведения доступны после входа;
  без авторизации очередь возвращает 401.
- После настоящего входа в браузере видна кнопка КП, открываются очередь
  и окно подключения с замаскированным полем Cookie.
- Пустая строка Cookie отклоняется до отправки; Escape закрывает окно.
- Реальные API-отчёты начала/завершения воспроизведения создали одну оценку.
- Отдельный пользователь воспроизвёл настоящий 12-секундный MP4 в Chrome.
  Во время просмотра окно оценки не появлялось. После естественного окончания
  браузер отправил отчёт завершения, и окно оценки появилось автоматически.
- Попытка поставить 8 без подключённого аккаунта возвращает предложение
  подключить Кинопоиск, без ложного сообщения об успешной отправке.

Отдельной страницы параметров в панели плагинов в 0.2.0 нет. Подключение:
**КП справа внизу → Подключение Кинопоиска**.

## Проверка версии 0.3.0

В 0.3.0 плавающая кнопка удалена, а подключение и очередь перенесены на
штатную страницу плагина: **Панель управления → Плагины → Мои плагины →
Kinopoisk Ratings → Настройки**. Прямой маршрут:
`/web/#/configurationpage?name=KinopoiskRatings`.

Проверки версии 0.3.0 прошли:

- `live_settings_smoke.cjs`: карточка плагина → «Параметры», без автоматической вставки `client.js`; статус, пользователь, Cookie и очередь доступны.
- `live_browser_smoke.cjs`: плавающей кнопки нет; из автоматического окна открываются штатные параметры.
- `live_video_smoke.cjs`: настоящее воспроизведение MP4 в Chrome, автоматическая оценка после окончания.
- `live_desktop_smoke.cjs`: настоящий JMP 1.12.0 (официальный jammy-пакет), QtWebEngine 5.15.9 / Chromium 87, MPV, Xvfb/Mesa. Страница параметров открылась, фильм воспроизведён нативным MPV (не HTML video), после окончания появилось окно оценки. Во время просмотра окна не было. Отправка без сессии Кинопоиска корректно отклонена.

Desktop проверялся отдельно в контейнере `jmp-kp-smoke-112` с профилем
`.research/jmp/runtime/home` и DevTools только на `127.0.0.1:18097`.
Использован стандартный запуск, без `--force-external-webclient`.
Профиль установленного Windows-клиента не изменялся.

## Запуск тестов

Тесты предназначены только для отдельного локального сервера. Не направлять
их на пользовательский/production сервер: они создают тестовых пользователей
и медиатеку. Файлы данных находятся в игнорируемой `.research/jellyfin-smoke`.

1. Поднять отдельный контейнер с портом `127.0.0.1:18096:8096`, отдельными
   `/config`, `/cache`, `/media`; установить в `/config/plugins` опубликованные
   DLL обоих плагинов. Не использовать данные действующего Jellyfin.
2. В тестовой `/media` нужен файл `Plugin Test (2026).mp4`, например 12-секундный
   testsrc2, созданный ffmpeg (H264/AAC). Тест присвоит ему фиктивное соответствие
   ID Кинопоиска 301 только для проверки очереди.
3. `npm install --prefix .research/browser playwright --no-audit --no-fund`.
   Браузерные тесты используют установленный Chrome (`channel: chrome`).
4. Выполнить из корня проекта:

```text
python tests/live_server_smoke.py
python tests/live_playback_smoke.py
node tests/live_browser_smoke.cjs
node tests/live_settings_smoke.cjs
node tests/live_video_smoke.cjs
```

Первый тест завершает мастер настройки чистого сервера с локальным тестовым
пользователем. Случайные пароли и токены сохраняются только в `.research`;
в вывод тестов они не попадают. Видео-тест создаёт нового пользователя при
каждом запуске, чтобы предыдущая очередь не влияла на результат.

Скриншоты: `.research/jellyfin-smoke/connection.png`, `plugin-settings.png`
и `after-playback.png`. При повторном запуске они отражают текущую проверяемую
версию, а не обязательно историческую 0.2.0.

## Границы проверки

Не проверены: реальная запись оценки в аккаунт Кинопоиска, Windows-сборка
Media Player, телевизоры, Kubernetes и просмотр сериалов.
Проверки не используют сессию Кинопоиска и не отправляют реальные оценки.

Для повторения desktop-теста нужен отдельный JMP с DevTools на localhost:18097, экраном Xvfb и доступом к тестовому серверу. Начальное состояние — страница входа в тестовый Jellyfin. Команда: `node tests/live_desktop_smoke.cjs`. `desktop_cdp.cjs` использует стандартный DevTools-протокол, потому что Qt не поддерживает управление браузерными контекстами Playwright. Скриншоты: `desktop-settings.png`, `desktop-after-playback.png` в тестовой папке.
